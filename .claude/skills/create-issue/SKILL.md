# GitHub 이슈 생성 스킬

이 스킬은 GitHub 이슈를 자동으로 생성합니다.

## 사용법

```
/create-issue 이슈 설명
```

## 주요 기능

1. **단일 이슈 생성**: 간단한 설명으로 이슈 생성
2. **태스크 기반 이슈 생성**: breakdown의 태스크를 GitHub 이슈로 변환
3. **자동 포맷팅**: 이슈 제목과 본문을 적절히 구성
4. **레이블 자동 할당**: 이슈 유형에 따라 레이블 추가 (옵션)

## 실행 프로세스

### 1. 입력 분석

사용자 입력(`도시 상세페이지를 만들고 싶어`)을 분석하여:
- 이슈 유형 파악 (feature, bug, enhancement, documentation 등)
- 주요 키워드 추출
- 우선순위 판단 (명시된 경우)

### 2. 이슈 제목 생성

명확하고 간결한 제목 생성 규칙:
- **Feature**: `[Feature] {기능 설명}`
- **Bug**: `[Bug] {버그 설명}`
- **Enhancement**: `[Enhancement] {개선 사항}`
- **Documentation**: `[Docs] {문서 내용}`
- **기타**: `{설명}` (태그 없음)

예시:
- 입력: "도시 상세페이지를 만들고 싶어"
- 제목: `[Feature] 도시 상세페이지 구현`

### 3. 이슈 본문 구성

구조화된 이슈 본문 생성:

```markdown
## 📋 설명
{사용자 요청 내용을 확장하여 명확하게 설명}

## 🎯 목표
- [ ] {구체적인 달성 목표 1}
- [ ] {구체적인 달성 목표 2}
- [ ] {구체적인 달성 목표 3}

## 📝 상세 내용
{필요한 경우 기술적 세부사항, 요구사항, 제약사항 등 추가}

## ✅ 완료 조건
- [ ] {검증 가능한 완료 조건 1}
- [ ] {검증 가능한 완료 조건 2}
- [ ] {검증 가능한 완료 조건 3}

## 🔗 관련 정보
{관련 파일, 문서, 이슈 링크 등}
```

### 4. GitHub CLI로 이슈 생성

`gh issue create` 명령 사용:

```bash
gh issue create \
  --title "{제목}" \
  --body "{본문}" \
  --label "{레이블1},{레이블2}" \
  --assignee "@me"  # 옵션
```

### 5. 결과 확인 및 보고

- 생성된 이슈 URL 반환
- 이슈 번호 표시
- 할당된 레이블 확인

## 고급 기능: Breakdown 통합

breakdown 스킬과 함께 사용 시, 여러 태스크를 개별 이슈로 변환:

### 사용 예시
```
/breakdown 도시 상세페이지를 만들고 싶어
(breakdown 결과 확인 후)
/create-issue --from-breakdown
```

### 동작 방식
1. 현재 세션의 breakdown 결과 파싱
2. 각 Phase의 태스크를 개별 이슈로 생성
3. 의존성을 이슈 본문에 명시
4. 마일스톤 생성 (옵션)

### 이슈 본문 예시 (breakdown 기반)
```markdown
## 📋 태스크 설명
{Task description}

## 📂 관련 파일
- `{file_path:line_number}`

## ⏱️ 예상 시간
{estimate} 시간

## 🔗 의존성
- Depends on: #{이슈번호}
- Blocks: #{이슈번호}

## ✅ 완료 조건
- [ ] {Definition of Done 1}
- [ ] {Definition of Done 2}

## 🏷️ 메타데이터
- **Phase**: {phase_name}
- **Priority**: {priority}
- **Complexity**: {complexity}
```

## 레이블 자동 할당 로직

키워드 기반 레이블 할당:

| 키워드 | 레이블 |
|--------|--------|
| 버그, 오류, 에러, 작동 안 함 | `bug` |
| 기능, 추가, 구현, 만들다 | `feature` |
| 개선, 향상, 최적화, 리팩토링 | `enhancement` |
| 문서, 가이드, 설명 | `documentation` |
| 테스트, 검증 | `testing` |
| 디자인, UI, UX | `design` |
| 성능, 속도, 최적화 | `performance` |
| 보안, 인증, 권한 | `security` |

우선순위 레이블:
- `priority: high` - "긴급", "중요", "critical"
- `priority: medium` - 기본값
- `priority: low` - "나중에", "옵션"

## 실행 단계별 가이드

### Step 1: 리포지토리 확인
```bash
gh repo view --json name,owner
```
- 현재 디렉토리가 git 리포지토리인지 확인
- GitHub 리포지토리와 연결되어 있는지 확인

### Step 2: 입력 파싱
사용자 입력을 분석하여:
- 이슈 타입 추출
- 핵심 키워드 식별
- 우선순위/긴급도 파악

### Step 3: 이슈 내용 생성
- 제목: 간결하고 명확하게 (50자 이내 권장)
- 본문: 구조화된 마크다운 형식
- 체크리스트: 구체적이고 실행 가능한 항목

### Step 4: gh CLI 실행
```bash
gh issue create \
  --title "[Feature] 도시 상세페이지 구현" \
  --body "$(cat <<'EOF'
## 📋 설명
도시별 상세 정보를 표시하는 페이지를 구현합니다.

## 🎯 목표
- [ ] 동적 라우팅 설정 (/cities/[id])
- [ ] 도시 정보 표시 컴포넌트 개발
- [ ] 기존 페이지에서 링크 연결

## ✅ 완료 조건
- [ ] 모든 도시 페이지 접근 가능
- [ ] 반응형 디자인 적용
- [ ] SEO 메타데이터 설정
EOF
)" \
  --label "feature,enhancement"
```

### Step 5: 결과 반환
```
✅ 이슈가 생성되었습니다!
📌 이슈 번호: #42
🔗 URL: https://github.com/user/repo/issues/42
🏷️ 레이블: feature, enhancement
```

## 에러 핸들링

### gh CLI 미설치
```
❌ GitHub CLI(gh)가 설치되지 않았습니다.
설치 방법: brew install gh
```

### 인증 필요
```
❌ GitHub 인증이 필요합니다.
실행: gh auth login
```

### 리포지토리 없음
```
❌ 현재 디렉토리가 GitHub 리포지토리가 아닙니다.
git remote -v로 확인하세요.
```

## 커스터마이징 옵션

사용자가 추가 플래그를 제공할 수 있습니다:

```
/create-issue --title "커스텀 제목" --label "bug,urgent" 설명 내용
```

파싱 순서:
1. `--title` 플래그: 제목 직접 지정
2. `--label` 플래그: 레이블 직접 지정
3. `--assignee` 플래그: 담당자 지정 (@me, @username)
4. `--milestone` 플래그: 마일스톤 지정
5. `--priority` 플래그: high/medium/low
6. 나머지: 이슈 설명

## 베스트 프랙티스

1. **명확한 제목**: 이슈를 한눈에 파악할 수 있도록
2. **체크리스트 활용**: 진행 상황을 추적하기 쉽게
3. **관련 파일 명시**: 작업 범위를 명확히
4. **완료 조건 정의**: 언제 이슈를 닫을지 명확히
5. **레이블 일관성**: 프로젝트 전체에서 일관된 레이블 사용

## 예시

### 예시 1: 간단한 기능 요청
```
/create-issue 사용자 프로필 편집 기능 추가
```

생성되는 이슈:
```markdown
제목: [Feature] 사용자 프로필 편집 기능 추가

## 📋 설명
사용자가 자신의 프로필 정보를 수정할 수 있는 기능을 추가합니다.

## 🎯 목표
- [ ] 프로필 편집 UI 구현
- [ ] 프로필 업데이트 API 연동
- [ ] 유효성 검증 추가

## ✅ 완료 조건
- [ ] 사용자가 이름, 이메일, 프로필 사진 수정 가능
- [ ] 변경 사항이 데이터베이스에 저장됨
- [ ] 에러 처리 및 성공 메시지 표시
```

### 예시 2: 버그 수정
```
/create-issue 로그인 후 리다이렉션이 작동하지 않음
```

생성되는 이슈:
```markdown
제목: [Bug] 로그인 후 리다이렉션이 작동하지 않음

## 📋 설명
사용자가 로그인에 성공한 후 원래 페이지로 돌아가지 않고 홈으로 이동하는 버그

## 🐛 재현 단계
1. 로그아웃 상태에서 보호된 페이지 접근
2. 로그인 페이지로 리다이렉션됨
3. 로그인 성공
4. 원래 페이지 대신 홈으로 이동

## 🎯 예상 동작
로그인 성공 후 원래 접근하려던 페이지로 이동

## ✅ 완료 조건
- [ ] 로그인 후 원래 페이지로 정상 리다이렉션
- [ ] 리다이렉션 경로 테스트 작성
```

### 예시 3: 우선순위 및 레이블 지정
```
/create-issue --priority high --label "security,bug" XSS 취약점 수정 필요
```

## 구현 시 주의사항

1. **gh CLI 사용 전 확인**: `gh` 명령어 사용 가능 여부 체크
2. **입력 검증**: 빈 입력이나 너무 긴 입력 처리
3. **마크다운 이스케이핑**: 이슈 본문의 특수문자 처리
4. **에러 메시지**: 사용자에게 명확한 에러 안내
5. **결과 확인**: 이슈 생성 성공 여부 확인 및 URL 반환
