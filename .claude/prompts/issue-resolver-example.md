# GitHub 이슈 해결 자동화 예시

## 빠른 사용법

다음과 같이 Claude에게 요청하세요:

```
이슈 #<번호> 분석하고 해결 계획 세워줘
```

또는

```
GitHub issue <번호> 가져와서 어떻게 해결할지 계획 세워줘
```

---

## 📌 예시 1: 간단한 버그 수정

**입력:**
```
이슈 #23 분석하고 해결 계획 세워줘
```

**Claude의 작업 흐름:**

1. **이슈 조회**
   ```bash
   gh issue view 23
   ```

2. **이슈 분석**
   - 제목: "로그인 버튼 클릭 시 404 에러"
   - 라벨: bug, high-priority
   - 내용: 로그인 버튼 클릭 시 `/api/auth/signin` 엔드포인트가 없음

3. **코드베이스 탐색**
   - 로그인 관련 파일 검색
   - API 라우트 확인
   - 컴포넌트 구조 파악

4. **계획 제시**
   ```markdown
   # 이슈 #23: 로그인 버튼 클릭 시 404 에러

   ## 해결 계획

   ### Step 1: API 라우트 생성
   파일: `src/app/api/auth/signin/route.ts`
   - NextAuth SignIn 핸들러 구현
   - 적절한 에러 처리 추가

   ### Step 2: 환경 변수 확인
   파일: `.env.local`
   - NEXTAUTH_URL 설정 확인
   - NEXTAUTH_SECRET 존재 확인

   ### Step 3: 테스트
   - 로그인 버튼 클릭 테스트
   - 에러 로그 확인

   이 계획으로 진행하시겠습니까?
   ```

5. **사용자 승인 대기**

6. **승인 후 구현**

## 📌 예시 2: 기능 추가

**입력:**
```
이슈 #45 해결 계획 세워줘
```

**Claude의 작업:**

1. 이슈 내용: "다크모드 지원 추가"

2. 계획:
   ```markdown
   # 이슈 #45: 다크모드 지원

   ## Phase 1: 테마 시스템 구축
   - ThemeProvider 설정
   - 색상 변수 정의

   ## Phase 2: UI 컴포넌트 업데이트
   - 모든 컴포넌트에 다크모드 스타일 추가

   ## Phase 3: 테마 토글 버튼
   - GNB에 토글 버튼 추가
   - localStorage에 설정 저장
   ```

## 📌 예시 3: 리팩토링

**입력:**
```
GitHub issue 78 분석해서 리팩토링 계획 작성해줘
```

**Claude의 작업:**

1. 이슈: "CityCard 컴포넌트 성능 최적화"

2. 분석:
   - 불필요한 리렌더링 발생
   - props drilling 문제
   - 중복 로직

3. 계획:
   ```markdown
   ## 최적화 계획

   ### Step 1: React.memo 적용
   ### Step 2: useMemo로 계산 최적화
   ### Step 3: Context API로 props drilling 해결
   ### Step 4: 중복 로직 커스텀 훅으로 추출
   ```

## 🎯 고급 사용법

### 여러 이슈 동시 분석

```
이슈 #12, #13, #14를 분석해서 통합 해결 계획 세워줘
```

### 특정 파일에 집중

```
이슈 #56 해결하는데 src/components/ui/ 폴더만 수정하는 계획 세워줘
```

### 단계별 실행

```
이슈 #89 해결 계획 세우고, 첫 번째 단계만 먼저 실행해줘
```

## 🔧 커스터마이징

필요에 따라 계획 형식을 조정할 수 있습니다:

```
이슈 #100 해결 계획을
1. 타입 정의
2. 데이터 업데이트
3. UI 구현
순서로 세워줘
```

---

## ⚡ 자동화 팁

1. **이슈 템플릿 활용**: GitHub 이슈 템플릿으로 필요 정보 구조화
2. **라벨 활용**: bug, feature, refactor 등 라벨로 자동 분류
3. **체크리스트**: 이슈 본문에 체크리스트 포함하면 계획에 반영
4. **관련 PR**: 이슈에 연결된 PR이 있으면 자동으로 참고

---

## 📚 참고

- 계획은 항상 SOLID 원칙을 따릅니다
- 타입 안정성을 최우선으로 합니다
- 기존 코드 스타일을 유지합니다
- 각 단계는 독립적으로 실행 가능합니다
