# GitHub 이슈 해결 프롬프트

이 프롬프트는 GitHub 이슈 번호를 입력받아 이슈를 분석하고 해결 계획을 수립합니다.

## 사용법

```
/resolve-issue <이슈번호>
```

예시:
```
/resolve-issue 42
```

---

## 워크플로우

### 1단계: 이슈 정보 가져오기
- `gh issue view <이슈번호>` 명령어로 이슈 상세 정보 조회
- 이슈 제목, 본문, 라벨, 할당자, 댓글 등 모든 정보 수집

### 2단계: 코드베이스 분석
- 이슈와 관련된 파일 탐색 (Glob, Grep 활용)
- 현재 구현 상태 파악
- 관련 의존성 확인

### 3단계: 해결 계획 수립
다음 형식으로 상세 계획 작성:

```markdown
# 이슈 #<번호>: <제목>

## 📋 이슈 요약
- **상태**: <상태>
- **라벨**: <라벨 목록>
- **설명**: <이슈 내용 요약>

## 🔍 현재 상태 분석
- 관련 파일: <파일 목록>
- 현재 구현: <현재 상태 설명>
- 문제점: <발견된 문제>

## 📝 해결 계획

### Step 1: <단계명>
**파일**: `<파일 경로>`

**변경 내용**:
- <변경 사항 1>
- <변경 사항 2>

**이유**: <왜 이 변경이 필요한지>

### Step 2: <단계명>
...

## ✅ 검증 체크리스트
- [ ] <검증 항목 1>
- [ ] <검증 항목 2>
- [ ] TypeScript 에러 없음
- [ ] 빌드 성공
- [ ] 기존 기능 정상 작동

## 🎯 예상 결과
<이 계획을 실행했을 때 예상되는 결과>

## ⚠️ 주의사항
<구현 시 주의해야 할 점>
```

### 4단계: 사용자 승인
- 계획을 사용자에게 제시
- "이 계획으로 진행하시겠습니까?" 질문
- 승인 받은 후에만 구현 시작

### 5단계: 구현 (승인 후)
- 계획대로 단계별 구현
- 각 단계마다 검증
- 완료 후 이슈에 결과 보고

---

## 실행 예시 프롬프트

**사용자 입력:**
```
깃허브 이슈 #15 해결해줘
```

**시스템 실행:**
1. `gh issue view 15 --json title,body,labels,comments` 실행
2. 이슈 내용 분석
3. 관련 코드 탐색
4. 상세 계획 작성
5. 사용자에게 계획 제시 및 승인 요청
6. (승인 시) 구현 시작

---

## 팁

- 이슈가 복잡한 경우 여러 Phase로 나누기
- 각 단계는 독립적으로 실행 가능하도록 설계
- SOLID 원칙 준수
- 타입 안정성 최우선
- 기존 코드 스타일 유지
