# 🎯 GitHub 이슈 해결 프롬프트

아래 프롬프트를 복사해서 이슈 번호만 바꿔서 사용하세요!

---

## 📋 기본 프롬프트 (복사해서 사용)

```
GitHub 이슈 #<번호>를 분석하고 해결하기 위한 상세한 실행 계획을 작성해줘.

다음 단계로 진행해줘:

1. gh CLI로 이슈 정보 가져오기
2. 이슈 내용, 라벨, 댓글 분석
3. 관련 파일 탐색 (Glob, Grep 활용)
4. 현재 코드베이스 상태 파악
5. 다음 형식으로 상세 계획 작성:

# 이슈 #<번호>: <제목>

## 📋 이슈 요약

- 라벨: <라벨들>
- 작성자: <작성자>
- 내용: <이슈 본문 요약>

## 🔍 현재 상태 분석
### 관련 파일
- <파일 목록>

### 현재 구현
- <현재 상태>

### 문제점
- <발견된 문제>

## 📝 상세 실행 계획

```typescript

```

**이유**: <설명>

**체크리스트**:
- [ ] <작업 1>
- [ ] <작업 2>

### Step 2: 타입 체크

**목적**: <목적>

...

## 🚀 빠른 사용 예시

### 예시 1: 버그 수정
```
GitHub 이슈 #23을 분석하고 해결하기 위한 상세한 실행 계획을 작성해줘.
```

### 예시 2: 기능 추가
```
이슈 #45 (다크모드 추가)를 해결하기 위한 Phase별 계획을 세워줘.
SOLID 원칙을 준수하고 타입 안정성을 보장하는 방향으로.
```

### 예시 3: 리팩토링
```
GitHub issue 78번 보고 성능 최적화 계획 세워줘.
React 베스트 프랙티스를 따르고 불필요한 리렌더링을 제거하는 방향으로.
```

### 예시 4: 복잡한 이슈
```
이슈 #100을 분석해줘.
이슈가 복잡하면 여러 Phase로 나누고,
각 Phase는 독립적으로 실행 가능하도록 계획해줘.
Phase 3에서 했던 것처럼 상세한 실행 계획으로.
```

## 💡 고급 팁

## 📦 체크리스트 템플릿

계획 검토 시 다음을 확인하세요:

- [ ] 이슈 요구사항이 모두 반영되었는가?
- [ ] 각 Step이 명확하고 실행 가능한가?
- [ ] 타입 안정성이 보장되는가?
- [ ] 기존 코드와의 일관성이 유지되는가?
- [ ] Breaking Changes가 문서화되었는가?
- [ ] 검증 방법이 구체적인가?
- [ ] Phase 분리가 적절한가?
